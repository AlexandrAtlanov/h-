# eval. Локальная оценка решения (Роль 3)

Имитация платформы хакатона. Прогон любой версии решения на наборе вопросов
с эталонами и отчет по методике лидерборда, Score = 0.7 x Match + 0.3 x Win.

## Быстрый старт

```bash
# 1) смоук без ключей (мок-LLM, 5 вопросов)
bash eval/smoke.sh

# 2) регресс-проверки детекторов (15 кейсов, без LLM)
python -m eval.selfcheck

# 3) реальный прогон текущего репо на демо-наборе
set -a; source .env; set +a
python -m eval.run_eval --repo . --set demo --tag main-15.11
```

Отчет лежит в `eval/reports/<tag>/report.md`. Перегенерация без нового
прогона: `python -m eval.report --tag <tag>`.

## Состав

| файл | назначение |
|---|---|
| `run_eval.py` | раннер, собирает DATA_DIR как у платформы, запускает solution.py, baseline и все проверки |
| `judge.py` | судья по разделу 8 регламента, два раунда со сменой порядка, обнуление выдумок |
| `fabrication_check.py` | детектор выдумок без LLM, числа, пункты, статьи и номера документов против базы |
| `classify_answer.py` | поведение ответа (answered, refused, clarify) и метрика ложных отказов |
| `report.py` | сборка report.md из артефактов прогона |
| `prompts.py` | промпты судьи и классификатора, PROMPT_VERSION входит в ключ кэша |
| `common.py` | jsonl, digest, .env, LLM-клиент |
| `mock_llm.py` | детерминированный мок OpenAI-совместимого API на три эндпоинта |
| `selfcheck.py` | юнит-проверки детекторов без ключей |
| `smoke.sh` | приемочный тест конвейера целиком на мок-LLM |
| `kb_map.json` | машиночитаемая карта базы, 21 документ с key_clauses, связи, 21 ловушка, 12 тем вне базы |
| `kb_map.md` | человекочитаемый дубль карты и матрица типов вопросов по документам |
| `baseline/` | sample_submission организаторов, не менять |
| `dataset/` | наборы вопросов, `demo.jsonl` это 18 официальных, `main.jsonl` и `holdout.jsonl` в работе |

## Переменные окружения

Решение получает от платформы переменные `LLM_BASE_URL`, `LLM_API_KEY`,
`LLM_MODEL`, `EMB_MODEL`, `MAX_WORKERS`, `TOP_K`, `TIME_LIMIT_SEC`, их
передает раннер. Для судьи и классификатора служит `JUDGE_MODEL`, по
умолчанию берется `LLM_MODEL`. Ключи читаются только из окружения или
`.env` в корне репо и не попадают в логи и отчеты.

## Формат набора

Файл `dataset/<set>.jsonl`, по одному вопросу в строке. Обязательные поля
`id`, `question`, `golden`. Опциональные поля `category`, `kind` (plain,
dialog, false_premise, no_data), `golden_status` (answered, insufficient)
и `source_docs` с именами файлов базы для проверки промахов поиска.

Ответы baseline кэшируются в `reports/_cache/` по ключу из имени сета,
пути базы и пути baseline. После правки датасета с теми же id удалите кэш
или смените имя сета.

## Ограничения

- Судья приближает платформенного, промпт организаторов неизвестен.
- Детектор выдумок не видит числительные прописью и числа, которые
  встречаются в базе в другом контексте, например 90 из инъекции в ЮО-7.
  Такие случаи находит судья.
- `reports/` это рабочие артефакты, в git они не попадают, см. .gitignore.
