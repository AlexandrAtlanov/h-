# Юридический ассистент

Ассистент для сотрудников компании: отвечает на юридические вопросы по базе договоров, внутренних регламентов и законов. Каждый ответ опирается только на найденные положения базы и содержит ссылку на документ и пункт. Если подтверждения в базе нет, ассистент прямо говорит, чего не хватает, и не отвечает по памяти.

Состав решения:

- **веб-чат** (`app/`): диалог, панель подтверждающих фрагментов, просмотр документа с подсветкой пункта, каталог документов;
- **ядро** (`rag.py`, `agent.py`, `prompts.py`): поиск, формирование ответа, проверка достоверности, решение об отказе;
- **сабмит для платформы хакатона** (`solution.py`, `make_zip.py`, `build_index.py`);
- **локальная оценка качества** (`eval/`).

## Быстрый запуск

Нужны Docker и Docker Compose. Порт по умолчанию — `8000` (меняется переменной `APP_PORT` в `.env`).

```powershell
Copy-Item .env.example .env      # Linux/macOS: cp .env.example .env
# впишите в .env адрес API и ключ (см. «Настройка»)
docker compose up --build
```

После запуска откройте <http://localhost:8000>. При первом запуске строится индекс документов (до минуты), статус виден в интерфейсе.

Остановка:

```powershell
docker compose down
```

Индекс сохраняется в volume `index-cache`. При изменении базы знаний удалите volume и постройте индекс заново:

```powershell
docker compose down -v
docker compose up --build
```

## Порядок проверки основного сценария

1. Запустите приложение, как описано выше, и откройте <http://localhost:8000>.
2. Задайте обычный вопрос: «Какая арендная плата по договору с ООО «Северный Склад» и до какого числа её нужно вносить?» — ответ со ссылкой на договор № А-08/2024 и пункты 3.1–3.2.
3. Нажмите на источник под ответом — откроется полный документ с подсвеченным пунктом.
4. Проверьте сложные сценарии:
   - ложная предпосылка: «Почему по договору с ООО «Северный Склад» арендная плата 500 000 рублей в месяц?» — ассистент исправит сумму;
   - редакция на дату события: «Договор на 12 млн рублей заключали в августе 2024 года. Нужно ли было одобрение генерального директора?» — применяется редакция регламента, действовавшая в 2024 году;
   - нет данных в базе: «Какой размер пособия по беременности и родам?» — обоснованный отказ;
   - неоднозначный контрагент: «Подскажите гарантию по договору с «Альфой»» — уточняющий вопрос («Альфа-Трейд» или «Альфа-Трейдинг»);
   - непрофильный запрос: «Посоветуй рецепт борща» — вежливое объяснение границ компетенции.
5. Продолжите диалог уточняющим вопросом — ассистент учитывает историю.

## Настройка

Используется любой OpenAI-совместимый API. На платформе хакатона адрес и ключ передаются организаторами через переменные окружения; для локального запуска впишите их в `.env` (файл не попадает в git).

| Переменная | Назначение | Пример |
|---|---|---|
| `LLM_BASE_URL` | адрес API (`/chat/completions`, `/embeddings`, `/rerank`) | `https://your-proxy.example/v1` |
| `LLM_API_KEY` | ключ API | — |
| `LLM_MODEL` | модель ответа | `deepseek/deepseek-v4.1-flash` (DeepSeek V4.1 Flash) |
| `EMB_MODEL` | модель эмбеддингов | `baai/bge-m3` |
| `EMB_BASE_URL`, `EMB_API_KEY` | отдельный адрес и ключ для эмбеддингов (по умолчанию как у LLM) | — |
| `RERANKER_MODEL` | реранкер, необязателен; пусто — выключен | Qwen3 Reranker 8B |
| `RERANKER_BASE_URL`, `RERANKER_API_KEY`, `RERANKER_TOP_N` | настройки реранкера | `8` |
| `TOP_K`, `MAX_WORKERS`, `TEMPERATURE` | фрагментов на запрос (не меньше 8), параллельность, температура | `8`, `6`, `0` |
| `APP_PORT` | порт веб-чата | `8000` |

Как подключить ключ: скопируйте `.env.example` в `.env`, впишите `LLM_BASE_URL` и `LLM_API_KEY`, перезапустите `docker compose up`. Официальный `api.deepseek.com` поддерживает чат, но не `/embeddings`: без endpoint для `bge-m3` поиск автоматически работает только по BM25.

## Что умеет интерфейс

- чат с историей текущего диалога;
- статусы ответа: подтверждено документами, неполный ответ, нет подтверждения, уточнение;
- список подтверждающих фрагментов;
- открытие полного документа по клику на источник;
- подсветка найденного пункта в документе;
- каталог документов с поиском по названию, номеру и контрагенту;
- адаптивная раскладка для desktop и mobile;
- явные состояния подготовки индекса, ошибки и недоступности модели.

## Архитектура

```text
браузер ─> FastAPI (app/) ─> LegalService ─┬─> LegalAgent (agent.py, prompts.py)
                                           │      1. планировщик запросов          (1 вызов LLM)
                                           │      2. гибридный поиск rag.py        (BM25 + bge-m3 [+ реранкер])
                                           │         + соседние фрагменты, допсоглашения, другие редакции
                                           │      3. ответ или запрос допоиска     (1 вызов LLM, +1 при допоиске)
                                           │      4. самопроверка фактов           (без LLM; +1 вызов исправления)
                                           └─> API документов и фрагментов
platform ─> solution.py ─> тот же LegalAgent ─> submission.csv
```

**Поиск (`rag.py`).** Документы делятся на фрагменты по разделам и пунктам договоров и по частям статей законов. У каждого фрагмента есть карточка с метаданными: вид и номер документа, контрагент, дата, редакция, статус «утратил силу», связь с допсоглашением, номера пунктов. Поиск гибридный: BM25 (точные номера, суммы, названия) и векторы bge-m3 (смысл), объединённые через Reciprocal Rank Fusion. Фрагменты договора, номер или контрагент которого назван в вопросе, поднимаются выше; «Альфа-Трейд» не совпадает с «Альфа-Трейдинг». Если эмбеддер недоступен, поиск продолжает работать на BM25.

**Ответ (`agent.py`, `prompts.py`).** Планировщик переформулирует вопрос с учётом истории диалога и разбивает его на темы. К найденным фрагментам добавляются шапки документов, допсоглашения к договорам и тот же пункт другой редакции документа — чтобы модель могла выбрать редакцию, действовавшую на дату события. Модель отвечает только по фрагментам в формате «прямой ответ → документ и пункт → 2–4 предложения» и возвращает статус и использованные фрагменты.

**Проверка достоверности.** Каждое число, номер пункта, статьи и документа в ответе ищется в фрагментах, которые видела модель (функция `find_unsupported` в `agent.py`). При расхождении выполняется один вызов исправления; если неподтверждённые сведения остались, предложения с ними удаляются.

**Решение об отказе и уточнении** (правила в `prompts.py`):

| Ситуация | Поведение | Статус |
|---|---|---|
| ответ есть во фрагментах | ответ со ссылкой; отказ запрещён | `ANSWERED` |
| ложная предпосылка в вопросе | прямое исправление по документу | `ANSWERED` |
| подтверждена только часть | ответ на подтверждённое + чего не хватает | `PARTIAL` |
| темы нет в базе | обоснованный отказ без ответа по памяти | `REFUSED` |
| неясно, о каком договоре/контрагенте речь | уточняющий вопрос с вариантами | `CLARIFY` |
| противоправная просьба | отказ с разъяснением требований | `REFUSED` |
| непрофильный запрос | объяснение границ компетенции | `OFF_TOPIC` |

Инструкции внутри документов и реплик («игнорируй остальные документы», «ты теперь…») считаются данными и не выполняются; поддельные системные сообщения из истории диалога отбрасываются.

## Сабмит на платформу хакатона

```powershell
python build_index.py        # необязательно: заранее посчитать индекс в kb_index_data.py (нужен ключ)
python make_zip.py           # архив в dist/: solution.py, agent.py, prompts.py, rag.py, requirements.txt
```

`solution.py` читает `DATA_DIR/questions.csv` и архив базы, обрабатывает вопросы параллельно и пишет `submission.csv`. Он укладывается в лимит 20 минут: после 14-й минуты новые вопросы идут упрощённым путём (один вызов LLM), к 18-й минуте файл записывается в любом случае. `make_zip.py` проверяет, что в архиве нет ключей и библиотек вне разрешённого списка.

## Оценка качества

Папка `eval/` имитирует платформу: прогоняет решение на наборе вопросов с эталонами, оценивает ответы LLM-судьёй по методике лидерборда (0,7 × Match + 0,3 × Win) и отдельно считает выдумки и ложные отказы. Подробнее — в [eval/README.md](eval/README.md).

```powershell
python -m eval.selfcheck                                   # детекторы, без ключей
python -m eval.run_eval --repo . --set demo --tag my-run    # реальный прогон, нужен .env
```

Отчёт: `eval/reports/<tag>/report.md`. В `eval/kb_map.md` — карта базы знаний и список ловушек.

## Зависимости

Версии зафиксированы и входят в разрешённый организаторами список.

- `requirements.txt` — ядро и сабмит: `httpx`, `numpy`, `python-dotenv`;
- `requirements-app.txt` — веб-чат: `fastapi`, `uvicorn`, `pydantic`.

Docker-образ основан на `python:3.11-slim` и ставит оба файла.

## API

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/healthz` | состояние индекса и моделей |
| `GET` | `/api/meta` | версия и примеры вопросов |
| `GET` | `/api/documents` | каталог документов |
| `GET` | `/api/documents/{id}` | полный документ и его фрагменты |
| `GET` | `/api/chunks/{id}` | отдельный фрагмент |
| `POST` | `/api/chat` | ответ на вопрос и источники |

Пример запроса:

```json
{
  "message": "Какая арендная плата по договору?",
  "history": []
}
```

## Локальная проверка без ключей

Для проверки интерфейса без настоящего API запустите заглушку из `eval/`:

```powershell
python -m eval.mock_llm --port 9000
```

Затем в другом окне:

```powershell
$env:LLM_BASE_URL = "http://127.0.0.1:9000"
$env:LLM_API_KEY = "test"
pip install -r requirements.txt -r requirements-app.txt
uvicorn app.main:app --reload
```

Заглушка возвращает фиксированные ответы и нужна только для проверки интерфейса; в Docker-образ она не входит.

## Ограничения

- ассистент не использует внешние источники и собственные знания модели для юридических выводов;
- законы в базе представлены только в действующей редакции: если нужна старая редакция закона, ассистент сообщает, что её нет;
- самопроверка фактов эвристическая: она проверяет числа, пункты, статьи и номера документов, но не числительные прописью и не смысл утверждений;
- при отсутствии подтверждения в базе ответ не подменяется догадкой;
- без доступного endpoint эмбеддингов поиск работает в режиме BM25;
- API-ключи хранятся только в `.env` или секретах окружения;
- в базе тестовые документы вымышленной компании ООО «Меридиан», реальных внутренних документов банка нет.
